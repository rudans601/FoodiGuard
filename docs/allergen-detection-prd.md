# 알레르기 원료 판정 v2 — 2026-11-07

## 목표와 범위

19종에 대해 원재료와 확인된 표시문구에서 찾은 **함유 근거**, **혼입 주의 근거**,
**미확인**을 분리한다. 입력에 없는 성분을 없다고 판단하지 않는다.
최초 변경은 판정 모듈과 검증 도구에 한정했다. 이후 사용자가 실제 앱 DB의 신규 함유 근거 추가를
승인하여 아래에 기록한 575개 식품·576건만 반영했다. 스키마 변경과 앱 배포는 하지 않았다.
검색 API의 기존 저장 코드 기반 필터를 이 결과로 교체하려면 별도 검토가 필요하다.

## 입력과 출처

`assessAllergens({ ingredients, allergenStatements, precautionStatements })`의 각 필드는 문자열 배열이다.
상품명은 판정 입력으로 사용하지 않는다. 서로 다른 상품·제조원·규격·배합 시점의 자료를 합치지 않는다.
OCR 텍스트의 정확성, 라벨 식별, 자료 최신성 확인은 호출자가 수행해야 한다.
한국어 원재료와 지원하는 표시 문구를 대상으로 하며 모든 자연어·OCR 오탈자를 해석하는 모델이 아니다.

`deriveAllergens(names)`와 `matchesAllergen(label, name)`은 기존 호출부와 호환된다.
반환 `labels`, `codes`, `evidence`에는 긍정적인 함유 근거만 포함된다.

## 반환 계약

| 필드 | 의미 |
|---|---|
| `codes`, `labels`, `evidence` | 원료 사용 또는 명시된 함유 표시 근거. 잔류량 측정이나 섭취 안전 보장이 아님 |
| `mayContainCodes`, `mayContainLabels` | 같은 제조시설·혼입 가능 등의 주의 문구에 나온 성분 |
| `unknownIngredients` | 소스·분말스프·복합조미식품·불명확한 기원·향료 등의 원문과 이유 |
| `evidenceByCode` | 성분별 함유/혼입/부정 주장 근거. 출처 필드와 원문, 매칭 토큰 보존 |
| `assessments` | 19종 각각 `PRESENT`, `MAY_CONTAIN`, `UNKNOWN` 중 하나 |
| `sulfiteThresholdStatus` | 아황산계 원료 사용을 발견해도 최종 SO₂ 잔류량은 미평가 |

함유와 혼입 근거가 동시에 있으면 대표 상태는 `PRESENT`이고 두 근거는 모두 남긴다.
이는 조개류 안에서 굴 함유, 전복·홍합 혼입처럼 서로 다른 세부 성분의 근거도 보존한다.
무첨가·불검출·글루텐프리 주장은 별도 근거로 기록하며 `ABSENT`나 `SAFE` 상태를 생성하지 않는다.
함유와 부정 주장이 충돌하면 함유 근거를 유지하고 `conflict`를 기록한다.
명시적 근거를 찾지 못한 성분은 `UNKNOWN`이다. 복합원료가 없다는 사실도 무함유를 입증하지 않는다.

## 판정 규칙

- 식약처 원료 사전의 백태·서리태·검정콩·청태·노란콩·흑두를 대두에 연결한다.
- 오리알·거위알·칠면조알, 대하, 돈지·돈골·돈피, 소뼈, 황도·백도 등 명시적 원료명을 보강한다.
- 무유당우유에서 우유 근거를 제거하지 않는다. 밀크초콜릿은 우유 원료 근거로 분류한다.
- 돼지감자, 메밀, 밀크, 염소고기, 둥굴레 등의 충돌어는 해당 문자열만 가린다.
  같은 문장에 있는 다른 실제 원료까지 취소하지 않는다.
- 간장·사골·글루텐처럼 기원이 생략된 이름은 여기서 특정 원료 함유로 확정하지 않는다.
  세부 식품유형의 공식 정의와 제품 규격을 연결하는 추가 사전은 후속 검토 대상이다.
- 땅콩 또는 견과류가공품, 두부류또는묵류 등 대안이 있는 분류명은 미확인으로 남긴다.
- 향·맛·식물성 대체품의 이름만으로 동물/식물 기원을 확정하지 않는다.
- 복합원료의 일부 하위 원료가 보이면 그 근거는 활용하지만 전체 배합을 확보한 것으로 보지 않는다.
- 문장·괄호 범위를 분리해 `우유 함유, 메밀 혼입 가능`과
  `소스(우유, 글루텐프리전분)`에서 상태가 다른 성분으로 전파되지 않게 한다.
- `planAllergenUpdate`는 기존 저장 표시를 자동 삭제하지 않는다. 새로 발견한 함유 근거만 합치고,
  재검출되지 않은 기존 표시는 재검토 목록에 남긴다. 글자 충돌도 삭제 근거로 쓰지 않는다.

## DB를 변경하지 않는 전체 검증

기준 입력은 2026-09-11 보존 DB에서 읽기 전용 추출한 79,041개 식품과 901,315개 원재료 행이다.
현재 운영 DB 조회나 현재 판매 라벨 검증을 의미하지 않는다. 추가 필터 없이 모든 식품을 평가한다.
모든 상품·알레르기 조합 1,501,779개에 상태를 부여한다.

`backend/scripts/audit-allergens-offline.js`는 DB 모듈과 환경변수 파일을 불러오지 않는다.
`--apply` 옵션이 없고 추출본·원본 dump의 SHA256을 실행 전후 비교한다.
기존 코드가 없는 것을 정답으로 삼지 않으며, 신규 근거·재검토 대상을 별도로 집계한다.

실행 예시(저장소의 `backend` 디렉터리):

```sh
node scripts/audit-allergens-offline.js \
  --input ../../../output/validation/foodiguard-allergen-rule-review-20261107/snapshot-input.json \
  --manifest ../../../output/validation/foodiguard-allergen-rule-review-20261107/input-manifest.json \
  --baseline ../../../output/validation/foodiguard-allergen-rules-v2-20261107/baseline-allergens.mjs \
  --output /tmp/foodiguard-allergen-audit-new-run
```

출력의 `products.jsonl`에 식품별 19종 판정과 미확인 이유, 기존 코드와의 차이를 남긴다.
`summary.json`, `changed-ingredient-rules.json`, `unresolved-ingredients.json`으로 집계를 재검토할 수 있다.
출력 파일이 이미 있으면 덮어쓰지 않으므로 실행마다 새 출력 경로를 사용한다.

```sh
node --test --test-concurrency=1 --test-timeout=60000 server/allergens.test.js server/allergenAssessment.test.js
npm test
```

검토 전에 고정한 167개 사례, 19종별 문맥·기존 표시 보존 테스트, 사람이 확인했던 9개 라벨의
함유/혼입 목록을 검증한다. 9개는 검수된 목록의 분리 검증이며 원시 OCR 정확도 시험이 아니다.
전체 백엔드 테스트의 PGlite fixture는 임시 테스트 데이터만 사용하며 보존 DB나 운영 DB를 사용하지 않는다.

2026-11-07 검증 기록: 위 알레르기 테스트와 `server/recalculate.test.js`를 함께 실행한 307개는 통과했다.
`npm test` 전체 실행은 해당 환경에서 393개 통과 후 기존 `server/dataQuality.test.js`가 60초 제한으로
취소되었으며, 별도 실행에서도 재현되었다. 시간 초과의 원인은 확정하지 못했다.
전체 테스트 완료를 주장하지 않으며 이 문제를 피하려고 해당 테스트를 삭제·스킵하거나 제한을 늘리지 않았다.
이 작업의 전체 식품 검증은 DB/환경변수 모듈을 가져오지 않는 위 오프라인 명령으로 재현할 수 있다.

## 표시 의무와 데이터 한계

소스의 세부 원료 표시와 알레르기 표시는 별도 의무다. 복합원재료가 완제품 원재료 중량의 5% 미만이거나
복합원재료 안의 복합원재료인 경우에는 원재료 표시에서 명칭/식품유형만 표시할 수 있다.
그러나 표시 대상 알레르기 원료 및 그 유래 성분을 사용했다면 알레르기 표시 의무는 별도로 적용된다.
아황산류의 표시에는 최종 제품 SO₂ 10mg/kg 이상 등의 조건이 있고, 단일원료 제품명과 동일한 경우 등 예외도 있다.
DB의 원재료 필드만으로 실제 포장의 법 위반이나 무함유를 확정하지 않는다.

공식 근거:

- [식품등의 표시기준 고시 제2026-37호](https://www.mfds.go.kr/brd/m_211/view.do?seq=14968): 별지 1, 1.바.1).마), 복합원재료 표시 예외. 2026-11-07 HWPX 원문 확인.

자료별 시점/품목번호/식별 근거가 부족하면 미확인을 유지한다. 식품별 실제 배합의 정답 자료가 없으므로
전체 처리 건수나 회귀 테스트 통과율을 실사용 알레르기 검출 정확도로 표현하지 않는다.

## API를 제외한 후속 판별 방향

사용자 요청에 따라 추가 공공 API 수집과 외부 API 판정의 자동 반영을 제외한다.
기존 7,751개 재확인 대상의 저장 표시는 회피 필터에서 계속 유지하되,
새 근거로 재확인한 함유와 구분하는 검토 상태가 필요하다. 이 UI 변경은 아직 구현하지 않았다.

현재 DB의 수집 원문 79,041개를 기존 원재료와 비교했다. 괄호 안 쉼표를 보존하면
79,039개는 원재료와 동일하며, 2개는 `&#40;`/`&#41;` 문자 처리 차이다.
저장 과정에서 대량의 하위 배합을 잃었다는 근거는 찾지 못했다.

가장 먼저 검토할 추가 규칙은 **법정 식품유형의 필수 원료 관계**다.
식품공전 제2026-55호 제5의 13-2, 3-2, 12에 따르면 마요네즈에는 난황/전란,
화이트초콜릿에는 유고형분, 한식메주에는 대두의 사용 근거가 있다.
일반적인 제품명/맛 이름을 유형으로 오인하지 않도록 정확한 유형 식별을 먼저 확인한다.
소스·복합조미식품처럼 특정 알레르기 원료가 필수로 정해지지 않은 유형에는 확대 적용하지 않는다.

저장된 79,041개 전체에서 정확히 `마요네즈`라는 원재료가 있는 3,887개 중 난류 근거가 없는
2,363개, `화이트초콜릿` 536개 중 우유 근거가 없는 34개를 후속 검토 후보로 찾았다.
후보 수는 확정 추가 건수나 상품 전체의 알레르기 판명 완료 수가 아니다. 이 후보는 이번에 DB에 반영하지 않았다.
한 성분을 추가 확인해도 복합원료의 다른 성분과 혼입 가능성은 계속 미확인일 수 있다.

세부 구성은 제조사·원료 공급업체가 제공하는 알레르기 확인서/제품 규격서로 보완한다.
제조사, 원료 제품 코드, 공장, 배합 버전이 같은 경우에만 동일 근거를 재사용하며
`소스`라는 이름만 같은 여러 상품에 일괄 전파하지 않는다. 배합비 공개 대신
19종별 함유/혼입/미확인, 유효일, 원료 식별 정보를 받는 방식을 우선한다.
제조사에 실제 메시지나 요청을 전송하지 않았다.
